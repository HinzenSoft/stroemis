Nachgeholtes Speichern schreibt nie die fremde Seite

Stellt das Zeitfenster nach, in dem ein Speichervorgang seinen eigenen Editor überlebt: Seite R wird bearbeitet, die Anfrage bleibt hängen, währenddessen wechselt man zu Seite Q und tippt dort. Der nachgeholte Lauf darf danach nicht den Text von Q unter der Kennung von R ablegen. Diese Datei direkt im Browser öffnen (Doppelklick) – sie lädt die Skripte des Projekts über relative Pfade und braucht keinen Server; der Server ist hier durch eine Attrappe ersetzt, die jeden PUT so lange festhält, bis der Test ihn freigibt. Damit hängt nichts an Laufzeiten.
